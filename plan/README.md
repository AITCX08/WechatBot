# plan/ — 项目归档体系

> WechatBot 的全部规划与开发存档。**每次开发、修复、大模块代码操作完成后，都在对应目录留一份存档。**
> 结构沿用团队统一约定（参考 `Scout Agent/plan`），内容以本项目真实开发历史填充。

## 目录分类

| 目录 | 放什么 | 文件名示例 |
|------|--------|-----------|
| `开发规划/` | 技术方案、架构设计、需求（战略级蓝图） | `总体规划.md` |
| `实施计划/` | 可执行的 step-by-step 实施计划（writing-plans 产出放这里） | `2026-05-22-Weixin4迁移与自动下单.md` |
| `功能开发/` | 单个功能 / 模块的开发存档 | `2026-05-22-Dashboard看板.md` |
| `bug修复/` | 每次 bug 修复的存档 | `2026-05-23-Dashboard启动按钮无反应.md` |
| `重构与大模块/` | 大模块改造、架构级重构存档 | `2026-05-22-wcferry到WxAdapter迁移.md` |

> 需要新类型（如 `评审记录/`、`决策记录/`）随时加目录。

## 命名约定

`YYYY-MM-DD-<简述>.md`，按日期天然排序。`开发规划/` 里的长期蓝图可不带日期（用版本号，如 `_v2`）。

## 每份存档应包含（5 段式）

1. **背景** — 为什么做这件事（需求 / bug 现象）
2. **改了什么** — 涉及的文件 / 模块 / 接口（具体路径）
3. **为什么这么改** — 关键决策与权衡
4. **怎么验证** — 验收 / 测试 / 冒烟方式 + 结果
5. **关联** — 对应的 开发规划 / 实施计划 / commit

## 与 docs/superpowers、CHANGELOG 的关系

本项目早期文档落在 `docs/superpowers/`（superpowers 工作流产出），是带完整代码块的「权威细节版」。
三者分工：

- **`plan/`（本目录）** — 人读友好的分类归档；每篇自包含，文末交叉链接到细节文档
- **`docs/superpowers/plans|specs/`** — 可执行步骤 / 设计 spec（含大量代码块）
- **`CHANGELOG.md`（仓库根）** — 逐 commit / 逐里程碑的变更流水

## 存档时机（铁律）

- **每次功能开发完成** → `功能开发/`
- **每次 bug 修复完成** → `bug修复/`
- **每次大模块 / 重构操作** → `重构与大模块/`
- **写新方案 / 架构** → `开发规划/`；**拆 step-by-step 计划** → `实施计划/`
