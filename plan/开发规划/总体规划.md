# WechatBot 总体规划

> 日期：2026-05-31 ｜ 类型：战略蓝图 ｜ 状态：持续更新

## 背景

原项目（`lich0821/WeChatRobot`）依赖 `wcferry` + 微信 `3.9.12.51`。2026-05 起腾讯服务端拒绝该旧版
登录（扫码后手机端弹「该版本不允许登录」），且 wcferry 上游对微信 4.x 明确不打算适配。

调研结论（GitHub 全网搜索）：
- 无「免费 + 开源 + Python + Weixin 4.x hook」银弹，4.x 适配都藏在付费产品里
- `ylytdeng/wechat-decrypt`（3535★，活跃）可在 Weixin 4.x 实时解密 DB + 监听消息
- `uiautomation` 是 Windows 控件自动化事实标准，可驱动 Weixin 窗口发消息

## 技术选型

| 关注点 | 选型 | 理由 |
|--------|------|------|
| 接收消息 | wechat-decrypt sidecar（子进程 + SSE） | 现成成熟、与主项目解耦，只依赖 SSE 流 + DB 文件两个稳定接口 |
| 发送消息 | uiautomation 驱动 Weixin 窗口 | 不碰协议层，账号风险等同人工操作 |
| Web 看板 | FastAPI + Alpine.js（CDN，零构建） | 同进程跑，最低部署成本 |
| 登录方式 | 正常扫码（不伪造版本） | 服务端校验绕不过，伪造版本号触发风控；正常扫码风险最低 |

**核心原则**：不伪造版本、不碰协议层、账号风险等同人工。

## 架构总览

```
main.py → AccountManager（N 个独立账号）
            每账号: Robot + Dispatcher + OrderHandler + WxAdapter
                      WxAdapter = ContactsBackend + ReceiveBackend(SSE) + SendBackend(UIA)
旁路: Dashboard(FastAPI+SSE) / Notifier(filehelper) / Reporter(audit→日报)
```

详见 `plan/重构与大模块/2026-05-22-wcferry到WxAdapter迁移.md`。
